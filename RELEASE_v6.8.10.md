# PS Scanner Quant v6.8.10 — Precomputed Passive UI Views

v6.8.10 is a production-runtime reliability release based on the real-Mac v6.8.9 acceptance run.

## Production evidence

The v6.8.9 upgrade itself succeeded: checksum/archive integrity passed, Python 3.12.13 was selected, 320 local tests passed, Groww connected, the application reported 6.8.9, preserved runtime state remained intact, and post-install validation returned ok=true.

The validator also proved the v6.8.9 DB-snapshot change: health had zero request-path SQLite connections and a fresh execution snapshot, and the validator's performance query completed all 196 CLOSED rows on idx_recs_state_closed_perf_cover.

The subsequent live-worker stress pass exposed a different layer of contention:
- five health requests remained semantically correct and DB-free, but two were delayed into multi-second latency;
- passive performance hit its 2.5-second CPU/decode budget after loading only 31 rows;
- /api/international/board timed out after five seconds;
- /api/support/export timed out after thirty seconds.

These failures were not fixed by raising timeouts.

## v6.8.10 changes

### Health is now a pure memory view
The background health worker now owns broker-cache, Static-IP-cache, execution-readiness, trading-calendar, sector-status and history-control observations in addition to its DB snapshot. /api/health consumes that completed object plus in-memory worker liveness only. The request path performs zero SQLite, network, filesystem, settings, producer-refresh or history-pacer work.

A health snapshot older than 20 seconds still fails execution closed.

### Performance is precomputed
The normal website performance groupings are produced in a background worker. One complete CLOSED-ledger SQLite snapshot is used to derive all groupings in memory. The website's common /api/performance requests read a completed cache with zero request-path DB connections. Book-specific/nonstandard fallbacks retain the existing bounded fail-closed analytics path.

No partial statistics are ever presented as complete.

### International/Global-to-India page is precomputed
The complete International page payload — U.S. weekly book, Global-to-India long/short prediction books, provisional board and scan state — is built off-request and persisted. /api/international/board is a passive cache read.

### Export All Logs is prebuilt
The support ZIP is generated by a background worker and prebuilt once during installation while the service is stopped. The button only serves the latest complete archive.

The bundle still contains all retained application log files plus sanitized audit ledgers. It excludes credential/settings files, redacts known secrets and streams diagnostic rows as JSONL. ZIP_STORED is used to minimize runtime CPU/GIL cost. A failed refresh never replaces the previous complete bundle.

### Cooperative full-breadth scheduling
Global-to-India still evaluates the full NSE equity universe. Cooperative yields are more frequent in the summary and detail phases so the Python runtime can service passive HTTP work while research continues. No Top-N cap, score relaxation or scanner-frequency reduction is introduced.
